3. FILTERING LOGIC FOR SYSTEM APPS
================================================================================

ANALYSIS: System apps are NOT filtered out

In app_usage_service.dart lines 96-99:
  List<UsageInfo> filteredStats = usageStats.where((info) {
    int time = int.tryParse(info.totalTimeInForeground ?? '0') ?? 0;
    return time > 0;  // ONLY FILTER: usage time must be > 0
  }).toList();

This means:
  - System UI (if it has usage time) is counted
  - System services (if they have foreground time) are counted
  - Framework apps are included if they have usage time
  - Result: These system apps consume slots in the 10-app limit

The app includes system apps by passing (true, true) to InstalledApps.getInstalledApps():
  - First true: includeSystemApps
  - Second true: getIcons

================================================================================

ANDROID IMPLEMENTATION (FULLY SUPPORTED):
  Framework: Flutter with native Kotlin integration
  Service: AppUsageService + AppMonitoringService

    - UsageStats.queryEvents() - Get app launch events

  Real-time Monitoring:

  Permissions Required:
    - PACKAGE_USAGE_STATS (Usage Access)
    - ACCESSIBILITY_SERVICE (for monitoring/blocking)
    - SYSTEM_ALERT_WINDOW (for overlay)

iOS IMPLEMENTATION (NOT SUPPORTED):
  Framework: Flutter only (no native integration)
  Status: iOS APIs restrict third-party app access to usage statistics
  
  Fallback Behavior:
    - Shows error: "App usage tracking is only available on Android devices"
    - Uses hardcoded 6 apps: Instagram, Facebook, Twitter, YouTube, Snapchat, Netflix
    - Users can still select these apps manually
  
  Reason for Limitation:
    - iOS ScreenTime API requires MDM certificate
    - iOS restricts usage_stats and installed_apps plugins
    - No public API for third-party usage tracking

6. DETAILED ISSUE ANALYSIS - WHY ONLY 5-6 APPS
================================================================================

SCENARIO A: ANDROID USER ON HOME SCREEN
  Step 1: getTodayAppUsage() is called
    - Queries all apps with usage stats
    - Filters by time > 0
    - Sorts by usage time descending
    - LIMITS TO: top 10 apps (line 109)
    Result: 10 app objects returned
  
  Step 2: convertToDailyUsageApps() is called on the 10 apps
    - LIMITS TO: top 5 apps for chart display (line 74)
    - Assigns colors and calculates bar heights
    Result: 5 apps displayed in home screen chart
  
  Step 3: User navigates to "Select Apps" screen
    - Same getTodayAppUsage() returns 10 apps
    - _buildRealAppsList() displays all 10 apps
    - User can select from 10 apps maximum

SCENARIO B: ANDROID USER WITH SYSTEM APPS
  If device has high system app usage:
  - System UI might be #1 app with highest usage
  - System services might be #2-4 with significant usage
  - Actual user apps start at position #5
  - Home chart only shows top 5, so mostly system apps
  - User apps are pushed off the list

SCENARIO C: iOS USER
  - Platform.isAndroid check fails
  - getTodayAppUsage() returns empty list
  - _buildFallbackAppsList() is used instead
  - Shows hardcoded 6 apps: Instagram, Facebook, Twitter, YouTube, Snapchat, Netflix
  - These are static and never change
  - No real usage data is available

SCENARIO D: ANDROID USER WITHOUT PERMISSION
  - requestPermission() returns false
  - getTodayAppUsage() returns empty list
  - _buildFallbackAppsList() shows hardcoded 6 apps
  - Same as iOS fallback
